### 2. 系統啟動

#### `entry.S` 及其角色

`entry.S` 是 xv6 系統啟動過程中的第一個執行的代碼，它是用彙編語言編寫的，負責在系統啟動時設置基本的硬體環境並跳轉到 C 語言編寫的內核入口點。這個文件是整個系統啟動過程的基礎部分，主要處理以下幾個任務：

#### 1. 啟動代碼的位置和加載
- 在 `entry.S` 中，啟動代碼被放置在 `0x80000000` 位置，這是 RISC-V 架構下 QEMU 虛擬機器預設加載內核的位置。
- 當硬體啟動時，處理器將跳轉到這個地址執行啟動代碼。

#### 2. 設置堆棧指針
- `entry.S` 需要為每個 CPU 設置一個專用的堆棧。這是通過計算每個 CPU 的堆棧基址來完成的，這樣每個 CPU 都有獨立的堆棧空間來避免堆棧溢出或相互影響。
- 堆棧基址的計算基於 CPU 的 hartid（硬體線程 ID），並為每個 CPU 分配一個大小為 4096 字節的堆棧。

#### 3. 跳轉到 C 語言編寫的內核代碼
- 在完成硬體初始化後，`entry.S` 通過調用 `start` 函數進入 C 語言編寫的內核代碼。`start` 函數位於 `start.c` 中，是內核的主入口點。
- 在跳轉之前，`entry.S` 確保了系統的最基本環境已經準備好，使得後續的 C 語言代碼能夠在穩定的環境下執行。

#### `entry.S` 的代碼分析
```assembly
.section .text
.global _entry
_entry:
    # 設置堆棧指針
    la sp, stack0  # 加載堆棧基址
    li a0, 4096    # 每個堆棧的大小
    csrr a1, mhartid  # 獲取當前 CPU 的 hartid
    addi a1, a1, 1  # hartid + 1，從 1 開始計算堆棧
    mul a0, a0, a1  # 計算當前 CPU 的堆棧基址
    add sp, sp, a0  # 設置堆棧指針
    
    # 跳轉到 C 語言編寫的內核入口點
    call start

spin:
    j spin  # 若 `start` 返回，進入無限循環
```

#### 4. 小結
`entry.S` 在 xv6 系統啟動過程中扮演了關鍵角色。它負責將處理器從硬體啟動狀態轉換到可以運行 C 語言代碼的狀態，並為每個 CPU 設置堆棧指針，最終將控制權交給 `start` 函數進一步初始化內核。這一步是內核運行的基礎，也是理解 xv6 啟動過程的關鍵。
